# Database recovery

New empty databases must use `DATABASE_URL=... node server/scripts/bootstrap-empty-database.mjs` from the repository root. It refuses a destination containing public tables, applies the complete historical-schema baseline, records the existing migration checksums, then deploys later migrations. Existing databases continue to apply incremental SQL deliberately; do not baseline or reset Neon.

Before a release, take a PostgreSQL custom-format backup with `pg_dump --format=custom --no-owner --no-privileges --file=backup.dump`. Supply connection details through PostgreSQL environment variables or a permission-restricted service file; do not put passwords in shell history or commit backups. Keep a separate protected copy off the database host. Receipt images, sessions, customer data and audit records are sensitive. Access and retention require an explicit business policy.

Restore only into an empty, isolated database with `pg_restore --exit-on-error --single-transaction --no-owner --no-privileges --dbname=... backup.dump`. Validate all table counts, exact posted debit/credit totals, AR/AP ties, receipt-image hashes and append-only/closed-period controls before cutting over. Revoke restored sessions before exposing a restored application. A successful dump alone is not a recovery test.

For a repeatable local drill use `DRILL_SOURCE_URL=... DRILL_DESTINATION_URL=... node server/scripts/restore-drill.mjs`. Both URLs must be localhost; the destination must be empty and use a local PostgreSQL superuser. This portable logical drill bootstraps the complete schema, uses a private temporary compressed archive, preserves every typed value using PostgreSQL-quoted literals, including exact decimals, binary images and distinct SQL/JSON null values, compares every table hash, validates all foreign keys, checks posted ledger equality and retained control triggers, then deletes the archive. It excludes Prisma's migration bookkeeping from source data because bootstrap creates the current checksums. It is a test utility, not the production backup command. Production backup scheduling, retention and off-host recovery remain an operator responsibility on the free plans.
